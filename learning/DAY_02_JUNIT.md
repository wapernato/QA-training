# День 2 — JUnit 5 и тест-дизайн

В `ItemValidatorPracticeTest` есть только два примера. Вынеси валидатор в production-код и напиши минимум 10 параметризованных unit-тестов.

Обязательные классы эквивалентности и границы:

- `price`: -1, 0, 1, нормальная цена, `Long.MAX_VALUE`;
- `name`: null, пустая строка, пробелы, один символ, 120 и 121 символ;
- statistics: 0, положительное значение, -1;
- JSON API: отсутствующее обязательное поле и поле неверного типа.

Для каждого случая запиши ожидаемый результат до написания кода. Не превращай один тест в десять `assert` с разными данными — используй `@MethodSource` там, где данные имеют разную форму.
